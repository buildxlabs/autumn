# Loopback stream proxies: headers, manifests, prefetch and ranged sub-requests (#282)

## Verdict

The three references split the problem between them, and none of them has everything Phase 5 needs:

- **seanime** has the general-purpose HLS proxy: a URL with the target, a JSON header map and an HMAC token in the query string, full master/media playlist rewriting (`EXT-X-KEY`, `EXT-X-MAP`, relative URIs), 16-byte HLS key normalization, guarded redirects and literal `Range` passthrough. It does **not** rewrite DASH, prefetch segments or cache responses.
- **MovieBox-Tui** has the DASH sidecar: an in-process child that rewrites MPD `BaseURL`s, filters representations by height, injects a subtitle adaptation set, prefetches three segments ahead into a 24-entry cache, and splits `.m4s` segments into concurrent 95 KiB ranged sub-requests before serving the player's own `Range` from the assembled bytes. It has no token in the URL and its rewriting is string replacement, not MPD parsing.
- **VortX desktop** has no header injection, manifest rewriting or proxy token at all. Its "token gate" is a strict URL-shape check in the player: native mpv accepts only the exact `http://127.0.0.1:<bound-port>/<40-hex-infohash>/<decimal-index>` route the app itself bound, with no query. Bytes come from a separate streaming server dependency, not from the desktop code.

Autumn's `crates/relay` already owns the part the references are weakest at: a 128-bit per-session token, a strict path gate, `206`/`416` `Range` handling, cancellation on revoke and buffering events
([`crates/relay/src/lib.rs:54-87`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/lib.rs#L54-L87),
[`crates/relay/src/range.rs:24-76`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/range.rs#L24-L76),
[`crates/relay/src/serve.rs:47-130`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/serve.rs#L47-L130)). The Phase 5 gap is an upstream-fetching `/r/<token>/<id>` endpoint, not a new gate. The fit is: keep the token and the in-process axum server, take seanime's header allowlist and HLS rewrite shape, take MovieBox-Tui's prefetch/cache/range-splitting ideas, and send every upstream and redirected request through `net`'s outbound guard (ADR 0015) with secrets from the keychain (ADR 0002) rather than a query string.

For crates, `m3u8-rs 6.0.1` (MIT) is the maintained HLS read/write choice, and `dash-mpd-core 0.1.0` (MIT) is a better fit than `dash-mpd` for manifest rewriting because it parses and serializes MPDs without the downloader/muxer dependency tree.

## Autumn baseline

`crates/relay` today serves one route, `GET`/`HEAD /t/{token}/{hash}/{index}` on an OS-chosen `127.0.0.1` port
([`lib.rs:170-212`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/lib.rs#L170-L212)). It has no concept of an upstream URL, headers, cookies or manifests:

- `StreamToken` is a random 128-bit value, hex in the path, redacted in `Debug`, minted per stream and revoked on session end ([`lib.rs:54-87`, `224-260`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/lib.rs#L224-L260)).
- `parse_route` rejects queries, extra segments and non-numeric indices; the fallback is a uniform 404 ([`serve.rs:132-189`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/serve.rs#L132-L189)). This is the same shape VortX checks in the player.
- `range::resolve` handles `bytes=a-b`, `bytes=a-`, `bytes=-n`, uses the first spec of a multi-range request, clamps to EOF, and returns 416 for unsatisfiable ranges ([`range.rs:19-76`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/range.rs#L19-L76)). Responses carry `Accept-Ranges`, `Content-Length` and `Content-Range`; reads stream in 16 KiB chunks and report a stall after 2 seconds ([`serve.rs:41-45`, `78-129`, `231-310`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/serve.rs#L231-L310)).
- Reads come from a torrent `FileStream` and switch to the completed disk file at the same URL ([`lib.rs:262-273`](/Users/gaurav/.t3/worktrees/autumn/research-stream-relay-p-751b38b3926d95e6/crates/relay/src/lib.rs#L262-L273), ADR 0005).
- `engine → relay` is an allowed edge and `relay → domain` is listed in ARCHITECTURE §3; `relay → net` is **not** yet listed and must be added in the commit that introduces upstream fetching.

## seanime: a header-injecting HLS rewrite proxy

**URL and auth.** The player-facing route is `GET`/`HEAD /api/v1/proxy?url=<target>&headers=<JSON map>&token=<HMAC>`; the handler reads exactly those query parameters (`internal/handlers/proxy.go:206-233`), the route is registered without auth of its own (`internal/handlers/routes.go:135-136`), and `v1` uses `OptionalAuthMiddleware` (`routes.go:127`). The web client only builds the proxy URL when the source has headers; it then asks for a server-password HMAC token scoped to `/api/v1/proxy` (`seanime-web/src/app/(main)/onlinestream/_containers/onlinestream-page.tsx:590-605`, `_lib/onlinestream-proxy.ts:1-3`). The token is a base64url JSON blob `{endpoint, iat, exp}` plus an HMAC-SHA256 signature, with a 24-hour TTL and the server password (or a default secret) as key (`seanime-web/src/lib/server/hmac-auth.ts:18-62`); the server validates `?token=` against the request path (`internal/handlers/server_auth_middleware.go:42-53`). This is a server-auth token, not a per-stream secret, and it is echoed into every rewritten URI.

**Headers and cookies.** `headers` is a JSON object applied with `Header.Set` to the upstream request (`proxy.go:224-230`, `446-470`). Cookies are not a separate concept: a `Cookie` header in that map is injected like any other header. Blocked request headers are hop-by-hop headers plus `Accept-Encoding`, `Content-Length` and `Host` (`proxy.go:50-66`, `503-513`). Defaults are `Accept: */*` and a fixed Chrome 132 user agent when absent (`proxy.go:26-30`, `459-464`). The incoming client `Range` is copied verbatim to the upstream request (`proxy.go:465-467`). Response headers are copied back minus hop-by-hop headers, with permissive CORS headers added (`proxy.go:474-492`). Tests assert `Accept`, `Referer`, `User-Agent` and `Range` reach upstream while `Accept-Encoding` and `Connection` do not (`proxy_test.go:97-134`).

**Manifest rewriting.** HLS is detected by `Content-Type` containing `mpegurl` or a `.m3u8` path suffix (`proxy.go:494-501`). The body is decoded with `github.com/5rahim/hls-m3u8/m3u8` (`proxy.go:20`, `277-284`). On decode failure the raw bytes are forwarded, not an error (`proxy.go:278-284`).

- Media playlist: every segment URI, every `Keys[i].URI` (`EXT-X-KEY`), every `Map.URI` (`EXT-X-MAP`), partial-segment URIs, `PreloadHints.URI`, playlist-level `Map` and playlist-level `Keys` (`proxy.go:290-338`).
- Master playlist: each variant URI, each alternative rendering URI and each `SessionKeys` URI (`EXT-X-SESSION-KEY`) (`proxy.go:344-370`).
- Each URI is resolved as a reference against the playlist URL, lowercased to `http`/`https`, and abandoned unless it has a host; only then is it replaced with `/api/v1/proxy?url=...` carrying the same header map and token, plus `hlsKey=1` for key URIs (`proxy.go:393-444`, `520-537`). `isProxyURL` prevents double rewriting (`proxy.go:539-550`). The playlist is re-encoded only when at least one URI changed; otherwise the original bytes are served (`proxy.go:286-388`). Encoding is `application/vnd.apple.mpegurl`, with `Cache-Control: no-cache` added if the upstream omitted it (`proxy.go:380-385`).
- Keys get special handling: `hlsKey=1` reads at most 64 KiB, tries four base64 variants and accepts a decoded result only when it is exactly 16 bytes (AES-128), then serves it as `application/octet-stream` with the encoding header removed (`proxy.go:159-204`). The key URI itself is rewritten with the `hlsKey` flag set.
- There is **no DASH/MPD path**: `internal/handlers/proxy.go` contains no `dash` or `mpd` reference at the commit read.

**Prefetch and cache.** None in the video proxy: each request is an independent upstream GET and the response is streamed. seanime's adjacent systems do prefetch, but at different layers: `directstream` keeps a shared file-backed `httputil.FileStream` cache for multiple readers and passes the client `Range` upstream (`internal/directstream/httpstream.go:25-29`, `255-299`), and torrent streams preload the next episode's torrent at reduced speed so auto-next can start it (`internal/torrentstream/stream.go:702-776`). Neither is segment-level HLS/DASH prefetch.

**Redirects, timeouts, errors.** Four clients cover TLS verification strictness and HTTP/1.1 vs an HTTP/2 fallback (`proxy.go:68-75`). The primary transport pins `http/1.1` and disables compression; the fallback client is used only on negotiation errors ("no application protocol", unsupported protocol, malformed HTTP response, HTTP/2 handshake failure), not on stream errors (`proxy.go:77-157`, `proxy_test.go:21-95`). Transport timeouts: dial 30 s, keep-alive 30 s, TLS handshake 10 s, response headers 30 s, expect-continue 1 s, 100 idle connections / 10 per host / 90 s idle (`proxy.go:85-100`). Redirects are capped at 10 hops; in strict mode every redirect target is rechecked with `security.ValidateOutboundUrl` and rejected targets become 403 (`proxy.go:107-119`, `240-248`). That validator blocks `localhost` and loopback/private/link-local/multicast/unspecified IPs, resolving names with a 5 s timeout and checking every result (`internal/security/outbound.go:13-59`). Upstream failures become 502, bad input 400, out-of-bounds URL 403. HEAD requests are always GET upstream because some hosts mishandle HEAD, then return no body (`proxy.go:254-257`, `proxy_test.go:136-154`).

**Difference from Autumn.** seanime puts secrets in a URL query (logs, proxy history and mpv argv can capture them) and uses a 24-hour server token shared by all streams; Autumn's per-session 128-bit token and secret-free URL are safer. Its rewrite shape is nevertheless the best checklist for Autumn's HLS path. seanime's strict-mode URL check is weaker than ADR 0015: it resolves names once per check so DNS rebinding is not closed, and it has no declared-host list.

## MovieBox-Tui: DASH sidecar with prefetch and ranged sub-requests

MovieBox-Tui is dual-licensed: both `LICENSE-APACHE` and `LICENSE-MIT` are present. The upstream is `mesamirh/MovieBox-Tui`, not a fork with a different license.

**URL and auth.** There is no token. `spawn_sidecar` re-launches the app binary with `--proxy-for-vlc <target-url> <headers-json> <subtitle> <max-height>`, waits up to 8 seconds for the child to print `PORT <n>` on stdout, and returns `http://127.0.0.1:<port>/https/<host>/<path>` (or `/http/...`) to the player (`src/proxy.rs:105-175`). The `PORT` handshake and detached child are in `run_sidecar` (`proxy.rs:177-240`, `src/main.rs:70`). The sidecar is created eagerly for DASH URLs and for VLC/Android when headers go beyond `Referer`/`User-Agent` (`src/tui/app/playback.rs:337-370`, `421-447`). This sidecar model differs from Autumn: ARCHITECTURE §1 keeps one process and an in-process loopback server.

**Headers and cookies.** Auth headers arrive as CLI arguments, are stored in `ProxyContext.auth_headers` (`proxy.rs:80-90`) and are applied to upstream requests. For the original target host all configured headers are forwarded; for an allowed subtitle host only `User-Agent` and `Referer` are forwarded (`proxy.rs:286-288`, `362-378`, `483-487`). A `Cookie` header is just one of these headers (tests in `src/player.rs:1670-1696`, `src/cache.rs:919-953`). The host allowlist rejects any extracted host that is neither the original target nor the subtitle host with 403 (`proxy.rs:362-376`). Only `Range` and `Connection: close` are read from the client's request headers; everything else from the player is ignored (`proxy.rs:322-350`). Secrets in argv are visible to other local processes, a worse property than Autumn's keychain-only rule (ADR 0002).

**Manifest rewriting.** Only DASH. A URL is DASH if its path ends in `.mpd` or contains `/dash/` (`src/player.rs:122-125`); the proxy also treats any successful response whose `Content-Type` contains `dash+xml` or `xml` as a manifest (`proxy.rs:513-523`). Manifests are capped at 10 MiB (`proxy.rs:13`, `521-538`). `rewrite_dash_manifest` is pure string work: it replaces `https://<host>/` and `http://<host>/` prefixes with the loopback proxy's `/https/<host>/` and `/http/<host>/`, optionally removes `<Representation>` blocks whose `height` exceeds `max_height`, and injects a subtitle `<AdaptationSet>` pointing at `/sub/<percent-encoded-url>` before `</Period>` (`proxy.rs:980-1109`). The rewritten bytes are cached in a one-entry manifest cache and served from memory on later GETs (`proxy.rs:380-404`, `539-567`). There is no HLS rewrite at all.

**Prefetch and cache.** On sidecar start with a DASH target, `warmup_dash_sidecar` fetches and rewrites the MPD, caches it, and fires background fetches for `init-stream<video-id>.m4s`, `init-stream3.m4s`, `chunk-stream<video-id>-00001.m4s` and `chunk-stream3-00001.m4s` (`proxy.rs:234-240`, `614-675`). On every `.m4s` request, `next_dash_segment_urls` derives the next three numbered segments from the numeric filename stem (preserving zero padding) and also the matching audio segment `chunk-stream3-*`, then spawns fetches for any not already cached or in flight (`proxy.rs:406-424`, `677-735`; `PREFETCH_LOOKAHEAD = 3` at line 19). The `SegmentCache` is a 24-entry FIFO over `(url, content-type, bytes)` with an in-flight map of `Notify`s so concurrent requests coalesce onto one fetch; segments are capped at 16 MiB (`proxy.rs:11-19`, `24-78`, `764-812`). This lookahead is format-specific: it assumes the `init-streamN`/`chunk-streamN-00001.m4s` naming scheme, so it is an idea to copy only if Autumn's sources use the same layout.

**Ranged sub-requests.** `fetch_m4s_chunked` asks upstream for `bytes=0-95027` (95 KiB) with auth headers. If the upstream answers `206`, it parses the total from `Content-Range`, requests the remaining 95 KiB windows in batches of 16 concurrent GETs, assembles the whole segment in memory, and caches it; if the upstream answers `200` it accepts the body as complete (`proxy.rs:814-898`, helpers `737-762`). A player's own `Range` header is then applied by slicing the assembled bytes and emitting `206` with `Content-Range`, `Accept-Ranges: bytes` and permissive CORS (`proxy.rs:425-476`). Tests prove a 240 KiB segment costs three upstream requests and a second read costs none (`proxy.rs:1353-1427`). This is the only reference that turns one player range into several bounded upstream sub-requests; seanime and Autumn pass the range straight through.

**Other requests, limits and errors.** Non-manifest, non-`m4s` requests are streamed from upstream with only `content-type`, `content-length`, `content-range` and `accept-ranges` copied back, plus CORS and a rewritten `Content-Type` for `.srt`/`.vtt` (`proxy.rs:478-503`, `899-944`). The client is HTTP/1.1 only with a 15 s connect timeout and 16 idle connections per host (`proxy.rs:183-188`). A 60 s per-chunk idle timeout breaks a stalled stream, and a watchdog exits an idle child after 600 s with no connections (`proxy.rs:14-15`, `209-221`, `580-594`). Bad paths give 400, disallowed hosts 403, oversized manifests and upstream failures 502 (`proxy.rs:352-376`, `465-475`, `491-502`, `525-538`).

**Difference from Autumn.** Useful mechanisms (bounded sub-request fan-out, in-flight coalescing, a small LRU/FIFO, manifest caching) are missing from `crates/relay`; the tokenless URL, argv secrets, one-entry manifest cache, hard-coded filename lookahead and text-based MPD rewrite should not be copied.

## VortX desktop: an exact-URL player gate, not a proxy

The native player accepts a stream only when all of these hold (`desktop/src-tauri/src/player.rs:305-340`):

- scheme `http`, authority exactly the `127.0.0.1:<port>` the app's own server reported, no query;
- path is exactly `/<40-hex-infohash>/<decimal-index>` with no extra segments;
- `localhost` is rejected because hosts-file resolution is mutable, and other loopback routes (`/yt`, `/proxy`, root) are rejected because the bundled server also serves redirect handlers. Tests enumerate accepted and rejected forms at `player.rs:887-1036`.

`play` first stops any existing player, refuses non-http(s) URLs and invalid resume positions, then refuses remote URLs entirely unless an attested mpv runtime exists; native playback is disabled on Windows pending bounded named-pipe reads (`player.rs:348-420`, `385-394`). mpv is spawned with forced security arguments (`--no-config`, `--load-scripts=no`, `--tls-verify=yes`, reconnect and demuxer TLS options) that cannot come from user config (`player.rs:64-75`). The server wrapper binds `127.0.0.1:0`, sets `proxy_insecure_tls = false` and `proxy_allow_loopback = false`, and exposes only its base URL and authority to the gate (`desktop/src-tauri/src/server.rs:38-87`).

**Difference from Autumn.** VortX proves the "re-check the URL at the player" backstop that Autumn's exact-segment check already implements (`crates/relay/src/serve.rs:168-189` comes from this reference, with its notice preserved). It contributes nothing to header injection, manifest rewriting, prefetch or ranges. Its gate has no per-session token: possession of the bound port and a well-formed path is enough, so any local process could request the route. Autumn's 128-bit token is a strict improvement, and ADR 0005's revocation on session end has no VortX equivalent.

## What maps onto Autumn

- **Keep the existing gate.** Reuse `StreamToken`, the strict parser, uniform 404s and revoke-on-end for `/r/<token>/<id>`. Do not adopt seanime's path token or MovieBox-Tui's tokenless loopback URL: ADR 0005 already settled per-stream tokens, and ARCHITECTURE §7 redacts tokens in logs.
- **Header/cookie injection belongs in the relay, sourced from the resolved source, not from the player URL.** seanime's JSON-in-query and MovieBox-Tui's argv both put secrets where other processes and logs can see them. ADR 0002 and ADR 0012 say secret values live only in the OS keychain; the online-stream adapter should hand the relay opaque ids/handles, never the secrets themselves. hop-by-hop stripping and the `Accept`/user-agent defaults are worth porting; the `Host`, `Content-Length` and `Accept-Encoding` blocks are essential.
- **HLS rewrite follows seanime's field list**, implemented with `m3u8-rs`. Resolve relative URIs against the manifest URL, require `http`/`https`, carry the stream token on every sub-request, mark key URIs for 16-byte normalization, skip already-rewritten URIs, and pass raw bytes through on decode failure.
- **DASH rewrite, if in scope, should use `dash-mpd-core`**, not `String::replace`. MovieBox-Tui shows the useful features (representation filtering, subtitle injection, manifest caching) but its prefix replacement misses relative and cross-host URLs.
- **Prefetch and caching are optional but bounded.** MovieBox-Tui's three-segment lookahead, 24-segment cap, in-flight coalescing and 16 MiB segment cap are a sensible starting shape; its filename arithmetic is not general.
- **Range strategy is a decision, not an implementation detail.** Autumn's torrent relay passes one `Range` through and serves exactly that span. MovieBox-Tui instead fetches the whole segment via 95 KiB sub-requests and then serves the player's range from cache. Both can coexist in one relay but they have very different bandwidth, latency and memory profiles.
- **Every upstream hop goes through `net`.** ADR 0015's pre-send check, validating resolver and guarded redirects must apply to the initial manifest, rewritten sub-requests and all redirects; a crafted manifest must not be able to point the relay at loopback or LAN hosts. This is stricter than seanime's strict mode and MovieBox-Tui's host allowlist.

## Open questions surfaced

These are decisions for the grilling tickets; the research does not choose between them.

1. **Token and URL shape for the new relay route.** Reuse the ADR 0005 per-session 128-bit token in `/r/<token>/<id>`, or add a second HMAC-style token like seanime's for the upstream fetch? How does the player receive the URL without leaking it into its argv or history?
2. **How secrets reach the relay.** Opaque source id resolved inside the relay from keychain/extension settings (ADR 0002/0012), or an in-memory handle minted by `onlinestream`? What blocks other local processes from reading the headers?
3. **Manifest rewrite scope for Phase 5.** HLS only, or HLS and DASH together? If DASH is in scope, typed `dash-mpd-core` rewriting versus seanime-style raw passthrough, and how much of `SegmentTemplate`, `BaseURL`, `Location` and DRM `ContentProtection` must survive? The map's "Not yet specified" section already asks which manifest parser enters `[workspace.dependencies]`.
4. **Low-latency HLS tags.** Does Phase 5 need `EXT-X-PART` / `EXT-X-PRELOAD-HINT` support, given `m3u8-rs 6.0.1` has no typed model for them?
5. **Prefetch policy.** Lookahead depth (MovieBox-Tui uses 3), whether to guess segment names numerically or parse the manifest, cache size and eviction, in-flight deduplication and whether prefetch shares `net`'s ~500 MB cache budget or gets its own cap.
6. **Ranged sub-request policy.** Pass the player's `Range` through (seanime/Autumn torrent), or split large segments into fixed 95 KiB windows with bounded concurrency and assemble in memory (MovieBox-Tui)? What is the memory cap, what happens on an upstream `200` to a `Range` request, and how are suffix/multi-range headers treated?
7. **Outbound guard coverage.** Are rewritten segment URLs and every redirect checked against the online-stream extension's declared hosts (ADR 0015), and how does a host change on redirect surface to the user?
8. **Redirect, timeout and error budget.** Whether to mirror seanime's 10-hop guarded redirects and HTTP/1.1-first fallback, which connect/header/chunk timeouts to use, and how upstream failures map to player-visible statuses (404/416/502) and to extension health.
9. **In-process versus sidecar.** Autumn's design is one process with an axum loopback server; MovieBox-Tui's detached sidecar isolates crashes but adds a process and argv secrets. Is in-process isolation sufficient for untrusted remote streams?
10. **Domain language.** Whether the glossary should gain terms for the relay's upstream fetcher, manifest rewrite, segment prefetch and ranged sub-request, or whether these stay implementation details of `relay` (no files were changed for this ticket).
