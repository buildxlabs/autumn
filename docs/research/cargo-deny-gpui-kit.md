# What cargo-deny rejects once gpui-kit is in the tree

Wayfinder ticket [#12](https://github.com/buildxlabs/autumn/issues/12)
(`wayfinder:task`, AFK), on the throwaway branch `task/cargo-deny-gpui-kit`.
Question: what does `cargo deny check` reject once `gpui-kit` is a workspace
dependency, and does the tree still build on the pinned Rust 1.100?

## Setup (what was changed, and what was not)

- Added `gpui-kit = "0.10"` (default features) to `[workspace.dependencies]` in
  the root `Cargo.toml`.
- Added `gpui-kit.workspace = true` to `[dependencies]` in
  `crates/autumn/Cargo.toml`. No Rust source was changed.
- `deny.toml` was **not** modified. `Cargo.lock` was regenerated by the build
  and is committed with the branch so the facts are reproducible.
- Resolved version: `gpui-kit v0.10.0`. Its direct dependencies are
  `gpui-base`, `gpui-component`, `gpui-kit-assets`, `gpui-pre` (build),
  `gpui-pre-macros` and `gpui-pre-platform`, all `0.10.0` / `0.3.12`.

Environment: rustc `1.100.0` (pinned in `rust-toolchain.toml`), cargo `1.102.0`
(huacnlee/cargo build), cargo-deny `0.21.0`, macOS/darwin. Relevant policy in
`deny.toml`: `[graph] all-features = true`; `bans.multiple-versions = "warn"`;
`bans.wildcards = "deny"`; `sources.unknown-git = "deny"` and
`unknown-registry = "deny"`; advisories fail on vulnerabilities;
`unmaintained = "workspace"`.

## Build result

`cargo build -p autumn` **succeeded** (exit 0) in **57.02 s** as a cold dev
build on rustc 1.100.0. The only diagnostic is cargo's `unused dependency`
warning for `gpui-kit` — expected, since no source uses the crate yet.
`pnpm test:rust` (cargo-nextest) also passed: 0 tests, exit 0.

`pnpm check` ran clippy (pass) and `cargo deny check` (pass) but stopped at
`pnpm lint:typos` because the `typos` binary is not on this plain shell's PATH;
`direnv allow`/`nix develop` supply it. This is an environment gap, not a
failure caused by gpui-kit.

## cargo-deny result: nothing is rejected

`cargo deny check` **exited 0**. Its final line:

```text
advisories ok, bans ok, licenses ok, sources ok
```

| Category                              | Errors | Warnings | Blocking?                                                     |
| ------------------------------------- | -----: | -------: | ------------------------------------------------------------- |
| Advisories (vulnerabilities)          |      0 |        0 | no                                                            |
| Advisories (unmaintained)             |      0 |        0 | no — `unmaintained = "workspace"`, no direct unmaintained dep |
| Licenses                              |      0 |        0 | no                                                            |
| Bans — wildcards                      |      0 |        0 | no                                                            |
| Bans — multiple versions (duplicates) |      0 |   **68** | no — `multiple-versions = "warn"`                             |
| Sources — git dependencies            |      0 |        0 | no                                                            |
| Sources — unknown registries          |      0 |        0 | no                                                            |

So, with the policy as written today, **adding gpui-kit 0.10 with default
features requires no exception at all**. The only output is 68 duplicate-version
warnings, which would become rejections only if `bans.multiple-versions` were
flipped to `"deny"` (or warnings escalated with `-D warnings`).

### Advisories

Zero. No `RUSTSEC-*` identifier appears anywhere in the output; no advisory or
unmaintained-crate diagnostics were emitted.

### Licenses

Zero failures, and zero license warnings. No crate was reported as unlicensed,
unknown-licensed, or carrying a license outside the GPL-3.0-compatible
allow-list, despite `confidence-threshold = 0.93`. In particular `r-efi`
(5.3.0 and 6.0.0) is flagged only as a duplicate, not as a license problem —
its `MIT OR Apache-2.0 OR LGPL-2.1-or-later` expression is already allowed.

### Sources (git deps)

Zero. Every entry in `Cargo.lock` is
`registry+https://github.com/rust-lang/crates.io-index`; `grep -c 'git+'
Cargo.lock` is 0. No git dependency is introduced anywhere in the gpui-kit
tree, so `unknown-git = "deny"` never fires.

transitive from `autumn -> gpui-kit v0.10.0`** — none comes from Autumn's own
code. cargo-deny already prints the full reverse-dependency path under each

They cluster into a handful of root causes in the gpui-kit tree:

- **Windows target crates** (~24 of the 68): `gpui-base`/`gpui-component` pull
  `windows` 0.58 while `gpui-pre-windows` (`accesskit_windows`, `gpu-allocator`
  via `wgpu`) pulls 0.62; `zed-font-kit` pulls `windows-sys` 0.48,
  `ring`/`rustls` pulls 0.52, and `async-io`/`smol` pulls 0.61.2;
  `gpui-pre-reqwest` pulls `windows-registry` 0.4 while `gpui-pre-windows`
  pulls 0.6.1, producing the three-way split in `windows-targets` and the
  `windows_*` target crates.
- **Linux D-Bus**: `zbus` 5.19.0 via `gpui-pre-linux -> accesskit_unix`/`ashpd`/
  `oo7`, versus 6.5.0 via `notify-rust`. `zbus_macros` follows the same split.
- **TOML/proc-macro**: `winnow` 0.7.15 (`toml` 0.8 via `cbindgen` and
  `rust-i18n`) versus 1.0.5 (`toml` 1.2 via `embed-resource`, and `toml_edit`
  0.25 via `proc-macro-crate`); `toml_datetime` and `serde_spanned` follow.
- **RNG/crypto**: `getrandom` 0.2/0.3/0.4, `rand` 0.8/0.9, `rand_core`,
  `sha2`, `digest`, `block-buffer`, `crypto-common`, `cpufeatures`, `r-efi`,
  `redox_users`.
- **Graphics/font/SVG**: `resvg`/`usvg` 0.45 (via `gpui-component`) versus 0.46
  (via `gpui-pre`), and the associated `zune-*`, `png`, `gif`, `imagesize`,
  `read-fonts`, `skrifa`, `font-types`, `kurbo`, `roxmltree`, `svgtypes`,
  `miniz_oxide`, `hashbrown`, `itertools`.
- **macOS Objective-C bindings**: `objc2` 0.5/0.6, `objc2-app-kit`,
  `objc2-foundation`, `core-foundation`.
- **General util/proc-macro**: `syn` 2/3, `thiserror` 1/2 (+ `-impl`), `heck`,
  `phf` (+ `-generator`, `-shared`), `bitflags`, `base64`, `dirs`/`dirs-sys`,
  `rustc-hash`, `spin`.

## Facts for the later decision

- `cargo deny check` is green today with gpui-kit 0.10 default features; no
  license, advisory, source or wildcard exception is needed.
- The only pressure point is duplicates: 68 warnings, all transitive inside the
  gpui-kit/gpui-pre/gpui-component tree, most caused by version skew **between
  gpui-kit's own dependencies** (e.g. `windows` 0.58 vs 0.62, `zbus` 5 vs 6,
  `resvg` 0.45 vs 0.46) rather than anything Autumn chooses. Autumn cannot fix
  most of these by upgrading its own dependencies.
- If the policy is tightened to `bans.multiple-versions = "deny"`, all 68 must
  be addressed or explicitly skipped; the exception question is therefore
  sharp: accept the warnings as permanent signal, or tighten and carry skip
  entries. This graduated into
  [Which cargo-deny exceptions do we accept for the GPUI tree?](https://github.com/buildxlabs/autumn/issues/22).

## Reproduce

```sh
git checkout task/cargo-deny-gpui-kit
cargo build -p autumn
cargo deny check
cargo tree -i <crate>@<version> --target=all
```

The branch keeps the manifests, the regenerated `Cargo.lock` and this document;
`deny.toml` is untouched. No PR was opened.
